# Offline packet fixtures

Fixtures live in two places:

- `src/dcpstudio/fixtures.py` — hex constants used by the runtime self-test and
  the unit tests, so the application can validate its parser without files.
- `tests/fixtures/PROVENANCE.md` — the same provenance statement for reviewers.

## Provenance

All frames are **synthetic**. They were generated by
`dcpstudio.mock.MockNetwork` using the block layouts verified against:

- rt-labs p-net `src/common/pf_dcp.c`, `src/device/pf_cmina.c`
- Wireshark `plugins/epan/profinet/packet-pn-dcp.c` (IEC 61158-6-10 §4.3)

No vendor capture, production capture, or customer data was used.

## Regenerating

```bash
uv run python tools/make_fixtures.py
```

The script writes `tests/fixtures/*.hex` and `tests/fixtures/session.pcap` from
the constants in `src/dcpstudio/fixtures.py` and the mock responder. Review the
diff before committing: a changed fixture means a change in the mock or codec.

## What the fixtures do **not** prove

- They do not prove interoperability with a real device.
- They do not validate vendor-specific blocks.
- They do not exercise Npcap/Windows or Linux driver behavior.
- They are not a substitute for the isolated-lab tests in
  [`lab-integration-tests.md`](lab-integration-tests.md).
